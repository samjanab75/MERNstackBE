Task 4

DOM, Virtual DOM & Reconciliation

1. What is DOM?

DOM stands for Document Object Model. The browser represents the HTML document as a tree of objects. JavaScript can use the DOM to read or change the page.

Think: HTML page → browser creates a tree → JavaScript can update it.

2. What is Virtual DOM?

In React discussions, the Virtual DOM refers to React’s in-memory representation of the UI. React uses its element tree and rendering process to determine what the browser DOM should become.

It is a lightweight representation used during React's UI update process.

3. DOM vs Virtual DOM

DOMVirtual DOM / React tree
Browser's actual document structureIn-memory representation used by React
Changes affect the browser documentHelps React calculate required UI changes
Managed by the browserManaged by React's rendering system
React does not update the whole browser DOM just because a component re-renders.

4. What is Reconciliation?

Reconciliation is the process React uses to determine how the current rendered UI should change when a new render result is produced.

Old UI result + New UI result → React figures out what needs to change.

5. What is Diffing?

Diffing is the comparison of the previous and new React element trees/results to identify differences.

Diffing = finding what is different between old and new UI descriptions.

6. How does React identify UI changes?

React compares the previous and new results. Element type, position, props and especially stable keys for lists help React determine what should be preserved, updated, added or removed.

React compares UI descriptions instead of blindly rebuilding the whole DOM.

7. Why is key important while rendering lists?

A key gives each list item a stable identity. React can use that identity to match items between renders and handle insertions, removals and reordering more correctly.

const users = [
  { id: 1, name: "Sam" },
  { id: 2, name: "Riya" }
];

users.map(user =>
  <p key={user.id}>{user.name}</p>
);
Use a stable unique ID when possible. Avoid using array index as a key when list items can be reordered, inserted or removed.

1. What is Rendering?

Rendering is when React calls a component to calculate the UI representation for the current props and state.

Component runs → React gets the UI description.

2. What is Re-rendering?

Re-rendering means React runs a component again to produce a new UI result after relevant changes, such as state or parent updates.

Re-render ≠ reload the browser page.

3. What causes a component to re-render?

  • Its state changes.
  • Its parent re-renders and React renders the child as part of that update, subject to optimization.
  • Its props change as a result of a parent update.
  • A context value it reads changes.
A re-render is a React rendering update, not a full browser refresh.

4. Does re-render recreate the complete browser DOM?

No. A component re-render produces a new React UI result. React then determines what actual DOM changes are necessary and applies the required updates.

Only the necessary DOM changes are committed; the entire page is not blindly recreated.

5. What happens during reconciliation?

React takes the new render result and compares it with the previous result. It determines which parts can be reused and which need updates, insertions or removals, then commits the necessary changes to the browser DOM.

Compare → decide → commit required UI changes.

6. Relationship: Virtual DOM, Diffing & Reconciliation

The React element tree provides a description of the UI in memory. During reconciliation, React compares the previous and new results; this comparison is commonly called diffing. React then commits the necessary DOM updates.

Simple idea: UI description → compare → update only what is needed.

7. Explain the React rendering process in your own words

When a React component runs, it returns JSX. React turns that JSX into a React element tree that describes the UI. When state, props or another relevant input changes, React renders again and gets a new result. React compares the old and new results during reconciliation, identifies the differences, and commits the required changes to the browser DOM. The browser then shows the updated UI.

Class answer: “React first creates a UI description from the component and JSX. When data changes, the component can render again. React compares the previous and new UI descriptions, finds the differences, and updates only the required parts of the browser DOM.”
